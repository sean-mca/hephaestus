    Private function `format_storage_path(model_id, filename) -> String`:
    - Returns `"{model_id}/{filename}"` — no prefix parameter because OpenDAL Operator root already includes the prefix per D-04 and Pitfall 1 from RESEARCH.md.

    Private async function `download_file(op: &Operator, path: &str) -> Result<Option<Vec<u8>>, ResolveError>`:
    - Call `op.read(path).await`
    - On `Ok(data)`: return `Ok(Some(data.to_vec()))`
    - On `Err(e)` where `e.kind() == ErrorKind::NotFound`: return `Ok(None)` (cache miss)
    - On other `Err(e)`: return `Err(ResolveError::Storage(format!("read {path}: {e}")))` per Pattern 5 from RESEARCH.md

    Public(crate) async function `download_model(op: &Operator, model_id: &str, cache_dir: &Path) -> Result<Option<PathBuf>, ResolveError>`:
    - Follow the exact same logic structure as `download_model_from_s3` in s3.rs (lines 36-120):
      1. Compute `final_dir = cache_dir.join(STORAGE_CACHE_SUBDIR).join(model_id)`
      2. Return `Ok(Some(final_dir))` if final_dir already exists (local cache hit, log at debug level)
      3. Try downloading ONNX file: iterate `MODEL_ONNX` then `ONNX_SUBDIR_MODEL`, call `download_file` with `format_storage_path`
      4. If no ONNX file found, return `Ok(None)` (cache miss)
      5. Download `TOKENIZER_JSON` and `CONFIG_JSON` — return `Ok(None)` if either is missing
      6. Atomic temp-dir-then-rename pattern (D-12): create parent dirs, `TempDir::new_in(parent)`, write files via `tokio::fs::write`, create subdirs if needed (for onnx/model.onnx), rename, call `keep()` to prevent destructor cleanup
      7. Log at info level on success
    - All `map_err` calls use `ResolveError::Storage(...)` not `ResolveError::S3(...)`
    - OpenDAL paths must NOT start with `/` (Pitfall 2 from RESEARCH.md)

    Public(crate) async function `upload_model(op: &Operator, model_id: &str, local_dir: &Path) -> Result<(), ResolveError>`:
    - Walk `local_dir` recursively using `tokio::fs::read_dir` (same pattern as `upload_files_recursive` in s3.rs lines 142-189)
    - For each file: compute relative path from local_dir, build storage path via `format_storage_path(model_id, &relative)`
    - Read file bytes with `tokio::fs::read(&path).await`
    - Write via `op.write(&storage_path, bytes).await` mapping errors to `ResolveError::Storage`
    - Log each uploaded file at debug level
    - Use `Box::pin` for recursive async calls (same pattern as s3.rs line 154)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env vars -> Operator | STORAGE_TYPE env var selects which backend to construct; untrusted input could specify unexpected backends |
| model_id -> storage path | User-supplied model_id becomes part of storage paths; path traversal risk |
| network -> storage backend | S3/GCS backends make network calls; credential chain must be secure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | storage.rs paths | medium | mitigate | validate_model_id() runs before any storage operation (existing T-03-01 mitigation, unchanged). format_storage_path uses only validated model_id. |
| T-06-02 | Tampering | STORAGE_TYPE env var | medium | accept | STORAGE_TYPE is set via k8s manifest, not user input. Internal service with controlled deployments. Config validation happens at startup (Plan 06-02). |
| T-06-03 | Information Disclosure | credential leakage | medium | mitigate | OpenDAL loads credentials from env/IMDS/IRSA internally; no credentials in code or config structs. No credential fields in Config struct. |
| T-06-04 | Elevation of Privilege | unauthorized storage access | medium | accept | IAM policies on the S3 bucket are external infrastructure controls; fs backend relies on OS file permissions. Both are outside application scope. |
| T-06-SC | Tampering | cargo install (opendal) | high | mitigate | opendal crate verified OK in Package Legitimacy Audit (4+ years, 290k weekly downloads, Apache project). No checkpoint needed for Rust crate. |
</threat_model>
