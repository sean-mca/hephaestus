<objective>
Add optional dynamic request batching as the final vertical slice. When BATCH_ENABLED=true, a background task collects requests over a configurable time window and runs batched ONNX inference. When disabled (default), requests flow through the existing direct path with zero overhead.

Implements D-06 (channel-based batcher), D-07 (zero-overhead bypass), D-08 (all profiles support batching), D-09 (batch config env vars), BTCH-01 (dynamic batching), BTCH-02 (disabled by default), BTCH-03 (configurable batch size and wait time).

Purpose: Enable throughput scaling via batched inference for high-traffic deployments.
Output: Working batcher module, config extensions, handler batching path, end-to-end batching capability.
</objective>

    Create the channel-based batcher module per D-06. Define BatchRequest struct with fields: prepared (PreparedInput), reply (oneshot::Sender of Result of serde_json::Value, CoreError). Implement Batcher::new() that creates a bounded mpsc channel with capacity = 4 * max_batch_size per rules/async-bounded-channel.md. Returns (Batcher, mpsc::Receiver of BatchRequest). Implement Batcher::submit(&self, prepared: PreparedInput) -> Result of serde_json::Value, CoreError: creates a oneshot channel, sends BatchRequest{prepared, reply: tx} into the mpsc. Awaits the oneshot receiver. Maps channel errors to CoreError::Inference.

    Implement batcher_loop async function: takes mpsc::Receiver of BatchRequest, Arc of Mutex of PipelineKind, max_batch_size (usize), max_wait (Duration). Loop: wait for first request via rx.recv(). If channel closed, break. Push first request into batch vec. Start a tokio::time::sleep deadline for max_wait. Use tokio::select! to collect more requests until batch.len() >= max_batch_size OR deadline fires OR channel yields None. After collection, lock the pipeline mutex, drain prepared inputs from batch vec into a Vec of PreparedInput (taking the prepared field), call pipeline.execute_batch(inputs). Unlock immediately after execute_batch returns. Fan results back: iterate batch and results in lockstep, send each result through its oneshot reply channel. If execute_batch returns a top-level error (e.g., ONNX failure for the whole batch), send that error to ALL pending oneshot channels. Use let _ = req.reply.send(result) to ignore send errors (receiver may have been dropped if the HTTP request timed out).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> API | untrusted HTTP input (text field) |
| handler -> batcher channel | internal boundary (mpsc within process) |
| batcher -> pipeline mutex | internal lock boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Denial of Service | Batcher unbounded queue | medium | mitigate | Use bounded mpsc::channel(4 * max_batch_size) per rules/async-bounded-channel.md. Backpressure propagates to HTTP handler when channel is full. |
| T-04-06 | Denial of Service | BATCH_MAX_SIZE too large | medium | mitigate | Validate at startup: reject batch_max_size > 64 or < 1. Log warning for values > 32. Combined with tokenizer truncation (512 tokens), max memory per batch is bounded. |
| T-04-07 | Denial of Service | Oneshot channel leak on panic | medium | mitigate | batcher_loop sends Err to ALL pending oneshot channels on any execute_batch failure. Uses let _ = reply.send() to handle dropped receivers. Wrap batch execution in error handling that resolves all channels. |
| T-04-08 | Denial of Service | Batcher task panic kills batching | medium | mitigate | If batcher_loop panics, mpsc::Sender::send returns error. Handler converts channel send error to CoreError::Inference and returns 500 to client. Service degrades gracefully -- individual requests fail but pod stays alive. |
| T-04-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages installed. tokio sync/time features are additive to existing dependency. ndarray already in workspace. |
</threat_model>
