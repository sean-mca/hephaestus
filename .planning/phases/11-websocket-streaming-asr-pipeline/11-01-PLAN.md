<objective>
Generalize PipelineKind to accept heterogeneous input types (text and audio) per D-01 and return typed output per D-02. This is the foundational type-system change that enables the ASR pipeline (Plan 11-03) and WebSocket integration without breaking existing text-based REST, gRPC, and batcher code paths.

Purpose: Enable PipelineKind to dispatch on input modality (text vs audio) so that ASR models and WebSocket streaming can be added without modifying handler logic. Typed PipelineOutput replaces raw serde_json::Value for compile-time safety.
Output: Updated PipelineKind with InferenceInput/PreparedData/PipelineOutput type system; all callers migrated.
</objective>

  <name>Task 1: Define InferenceInput, PreparedData, PipelineOutput types and update error handling</name>
  <files>crates/hephaestus-core/src/pipeline.rs, crates/hephaestus-core/src/error.rs, crates/hephaestus-core/src/lib.rs, crates/hephaestus-api/src/error.rs</files>
  <action>
In pipeline.rs, add the following type definitions (place them after the existing Entity and ClassifierOutput structs, before PreparedInput):

1. InferenceInput enum with two variants: Text(String) for text-based pipelines and Audio(Vec of f32) for ASR pipelines. Implement From of String for InferenceInput, returning the Text variant. This From impl is critical — it enables existing callers passing String to prepare() to continue working without modification (per D-01).

2. PreparedAudio struct with pub(crate) fields: features as ndarray::Array2 of f32 (holds mel spectrogram or reshaped raw waveform tensor), and raw_samples as Option of Vec of f32 (preserved for CTC models that may need original waveform length). Give it a constructor new_for_test(features, raw_samples) with pub visibility, mirroring PreparedInput::new_for_test.

3. PreparedData enum with two variants: Text(PreparedInput) and Audio(PreparedAudio). Add a pub method into_text(self) returning Option of PreparedInput that extracts the PreparedInput from the Text variant and returns None for Audio. This is used by the batcher path to extract PreparedInput from the generic PreparedData.

4. PipelineOutput enum with five variants: Classifier containing label (String) and score (f32), Embeddings(Vec of f32), Seq2Seq(String), TokenClassifier(Vec of Entity), and Asr(String). Add a pub method to_json returning serde_json::Value that matches on self and constructs the appropriate JSON object. Classifier produces an object with "label" and "score" keys, Embeddings produces "embedding", Seq2Seq produces "generated_text", TokenClassifier produces "entities" (entities must be serialized since Entity derives Serialize), and Asr produces "text". This to_json method is the single point where typed output converts to JSON for HTTP/gRPC responses.

In error.rs (hephaestus-core), add an InvalidInput(String) variant to CoreError with the error attribute "invalid input: {0}".

In lib.rs (hephaestus-core), add re-exports for InferenceInput, PreparedData, PreparedAudio, and PipelineOutput alongside the existing re-exports from pipeline module.

In error.rs (hephaestus-api), add a match arm in the From of CoreError for ApiError implementation: CoreError::InvalidInput(msg) maps to ApiError::BadRequest(msg). Also add a match arm in the From of ApiError for tonic::Status: the existing BadRequest arm already handles this, so only the From of CoreError needs updating.

Add unit tests in pipeline.rs tests module: verify InferenceInput::from("hello".to_string()) produces Text variant, verify PreparedData::into_text() returns Some for Text and None for Audio, verify PipelineOutput::to_json() produces correct JSON for each variant (Classifier, Embeddings, Seq2Seq, TokenClassifier, Asr).

Read batcher.rs, handlers.rs, and grpc/inference.rs before making changes to understand all call sites.

In pipeline.rs, update PipelineKind::prepare to accept input of type impl Into of InferenceInput (instead of String). Inside, call input.into() to get the InferenceInput value, then match on (self, input). For each existing text variant (Classifier, Embeddings, Seq2Seq, TokenClassifier) paired with InferenceInput::Text(text), call the inner pipeline's prepare(text) and wrap the result in PreparedData::Text. For any text variant paired with InferenceInput::Audio, return CoreError::InvalidInput with message "text pipeline requires text input, got audio". Leave no arm for a hypothetical Asr variant yet — that is added in Plan 11-03. Return type changes from Result of PreparedInput to Result of PreparedData.

Update PipelineKind::execute to accept PreparedData (instead of PreparedInput) and return Result of PipelineOutput (instead of serde_json::Value). Match on (self, prepared). For Classifier with PreparedData::Text(t), call the inner pipeline execute(t) and wrap in PipelineOutput::Classifier with label and score fields. For Embeddings with PreparedData::Text(t), wrap in PipelineOutput::Embeddings. For Seq2Seq with PreparedData::Text(t), wrap in PipelineOutput::Seq2Seq. For TokenClassifier with PreparedData::Text(t), wrap in PipelineOutput::TokenClassifier. For any mismatched pair, return CoreError::InvalidInput. Remove the serde_json::json! macro calls that previously wrapped output — PipelineOutput::to_json handles that in the caller.

Update PipelineKind::execute_batch to accept Vec of PreparedData (instead of Vec of PreparedInput) and return Vec of Result of PipelineOutput (instead of serde_json::Value). At the top of the method, extract PreparedInput from each PreparedData::Text item. If any item is PreparedData::Audio, return an error for that item. Convert the extracted Vec of PreparedInput into the flat tensors as before. Update all four batch_postprocess_* free functions to return Vec of Result of PipelineOutput instead of serde_json::Value — batch_postprocess_classifier wraps in PipelineOutput::Classifier, batch_postprocess_embeddings wraps in PipelineOutput::Embeddings, batch_postprocess_seq2seq wraps in PipelineOutput::Seq2Seq, batch_postprocess_token_classifier wraps in PipelineOutput::TokenClassifier. Remove all serde_json::json! wrapping from these functions.

In batcher.rs, update BatchRequest to hold prepared: PreparedData (was PreparedInput) and reply: oneshot::Sender of Result of PipelineOutput (was serde_json::Value). Update the Batcher::submit method signature to accept PreparedData and return Result of PipelineOutput. Update batcher_loop to collect Vec of PreparedData (instead of Vec of PreparedInput) from the batch requests, pass to execute_batch. Update the replies type annotation to use PipelineOutput. Update tests: the submit test should wrap PreparedInput::new_for_test in PreparedData::Text, and the reply should send Ok(PipelineOutput::Classifier with test label and score). The bounded channel test should construct PreparedData::Text(...) instead of bare PreparedInput.

In handlers.rs, update the infer handler. The prepare call pipeline.prepare(req.text) still compiles because String converts to InferenceInput via From (no change to this line). In the direct execution path, the output of pipeline.execute(prepared) is now PipelineOutput instead of serde_json::Value. After the timeout match that yields the output, call output.to_json() to get a serde_json::Value, then proceed with the existing model_id and latency_ms injection into the JSON object. In the batcher path, the output of batcher.submit(prepared) is now PipelineOutput — same treatment, call to_json() before JSON enrichment. Name the PipelineOutput variable "output" and the json value "json_output" or simply reassign with let mut.

In grpc/inference.rs, apply the same pattern as handlers.rs. The prepare and execute calls work identically. After obtaining PipelineOutput, call to_json(), then inject model_id and latency_ms, then serialize to result_json bytes.

Verify existing unit tests in handlers.rs and batcher.rs still pass (they test JSON shapes and channel behavior). The existing pipeline unit tests (mock pipeline, id2label, token_type_ids) should still pass since the Pipeline trait itself is unchanged.
