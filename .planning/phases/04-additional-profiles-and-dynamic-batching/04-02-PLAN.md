  <action>
    Implement TokenClassifierPipeline for NER/POS per-token labeling per PROF-04.

    **postprocess.rs (modify):**
    Add argmax_per_token function: takes logits slice of f32, num_tokens usize, and num_labels usize. The logits are a flattened (num_tokens, num_labels) tensor. For each token, find the index and score of the maximum logit across labels. Returns Vec of (usize, f32) tuples. Add merge_subword_entities function that takes: the per-token (label_index, score) predictions, the tokenizers::Encoding from the prepare step, and the id2label Vec reference. Uses encoding.get_word_ids() to map subword tokens to original word indices. For each word group (consecutive tokens sharing the same word_id), use the first token's prediction as the word's label. Skip special tokens (word_id is None). Look up label string from id2label. If the label starts with "B-" or "I-" extract the entity type; otherwise use the label directly. Build entity spans by tracking consecutive tokens with same entity type (B-X followed by I-X). Return Vec of Entity structs. Define the Entity struct in postprocess.rs as pub(crate) with fields: word (String), entity (String), score (f32), start (usize), end (usize). Make Entity derive Debug, Clone, Serialize.

    Add unit tests: test_argmax_per_token with known logits for 3 tokens and 4 labels, test_merge_subword_entities_simple (this may need to be an integration-level test if Encoding is hard to construct -- in that case, test the argmax_per_token function thoroughly and add a structural test for merge_subword_entities).

    **pipeline.rs (modify):**
    Add TokenClassifierPipeline struct with fields: session (Session), tokenizer (Tokenizer), id2label (Vec of String). Implement TokenClassifierPipeline::new(model_dir: &Path) -> Result constructor following ClassifierPipeline pattern including id2label loading from config.json via the extract_id2label helper. For prepare(), the method needs to return both the PreparedInput AND preserve the Encoding for merge_subword_entities. Since PreparedInput does not carry the encoding, add an encoding field to PreparedInput: pub(crate) encoding: Option of tokenizers::Encoding. Set encoding to Some(encoding.clone()) in TokenClassifierPipeline::prepare(), and None in all other pipelines' prepare(). Alternatively, re-tokenize in execute() -- but re-tokenization is wasteful. The PreparedInput field approach is cleaner. Update all existing prepare() implementations to set encoding: None.

    Implement Pipeline for TokenClassifierPipeline with Input=String, Prepared=PreparedInput, Output=Vec of Entity. The execute() method runs ONNX inference, extracts the output tensor as f32 (shape [1, num_tokens, num_labels]), calls argmax_per_token, then calls merge_subword_entities passing the encoding from prepared.encoding.unwrap(). Returns the Vec of Entity.

    Add PipelineKind::TokenClassifier(TokenClassifierPipeline) variant. Add dispatch arms to PipelineKind::prepare() and PipelineKind::execute(). The execute arm serializes as serde_json::json!({"entities": entities}).

    Update lib.rs re-exports to include TokenClassifierPipeline and Entity.

    **main.rs (modify):**
    Replace the TokenClassifier arm that currently returns an error with PipelineKind::TokenClassifier(TokenClassifierPipeline::new(&model_dir)?). Add TokenClassifierPipeline to imports.
