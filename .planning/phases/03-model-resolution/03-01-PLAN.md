## Phase Goal

**As a** Kubernetes operator, **I want to** specify only a model name and have the runtime automatically resolve ONNX files from S3 cache or HuggingFace, **so that** pods self-provision without requiring pre-downloaded model files.

<objective>
Build the hephaestus-resolve crate with HuggingFace download support and wire it into the binary startup, replacing the current MODEL_PATH requirement with automatic model resolution via MODEL_ID.

This is the first vertical slice: after this plan, a real operator can deploy with just MODEL_ID and the pod downloads the ONNX model from HuggingFace automatically. D-03, D-04, D-05, D-07, D-09 are implemented. S3 tier and Forge stub are added in Plan 03-02.

Purpose: Eliminate the manual model file provisioning requirement. Pod startup becomes self-sufficient for models with existing ONNX exports on HuggingFace.

Output: Working resolve crate with HF tier, wired into main.rs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator env vars -> ModelResolver | MODEL_ID, S3_BUCKET, FORGE_URL from k8s pod spec (operator-controlled) |
| ModelResolver -> HuggingFace Hub | Public HTTPS API for model downloads |
| ModelResolver -> local filesystem | Downloaded model files written to HF cache directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | MODEL_ID in cache path construction | medium | mitigate | Validate MODEL_ID contains only alphanumeric, hyphen, underscore, forward-slash, period characters. Reject path traversal components. hf-hub handles its own path safety for HF cache. |
| T-03-02 | Information Disclosure | Error messages and logs | medium | mitigate | Never log raw AWS credentials or HF tokens. aws-config and hf-hub handle secrets internally. Log only model_id, tier name, and sanitized error messages. |
| T-03-03 | Denial of Service | Large model downloads filling disk | low | accept | K8s ephemeral storage limits and pod resource quotas handle disk exhaustion. Not in scope for the resolver -- deployment-level concern. |
| T-03-SC | Tampering | cargo dependency installs | high | mitigate | Package Legitimacy Audit passed: hf-hub (OK, 555K/wk, official HuggingFace), thiserror (OK, ecosystem standard), tempfile (OK, ecosystem standard). No [ASSUMED] or [SUS] packages. |
</threat_model>
