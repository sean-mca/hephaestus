<objective>
Split the pipeline mutex into an RwLock so tokenization (prepare) runs concurrently across requests while inference (execute) retains exclusive access.

Purpose: Currently AppState holds Mutex of PipelineKind. Both prepare() (which only reads the tokenizer, taking &self) and execute() (which mutates the session, taking &mut self) acquire the same exclusive lock. This serializes tokenization unnecessarily. Replacing Mutex with tokio::sync::RwLock allows multiple concurrent read locks for prepare() while write locks serialize execute(). Addresses SC-02.

Output: Concurrent tokenization without holding the inference lock.
</objective>
