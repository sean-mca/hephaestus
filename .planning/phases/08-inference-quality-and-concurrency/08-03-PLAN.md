<task type="auto">
  <name>Task 2: Create integration test file with tests for classifier, embeddings, and token classifier profiles</name>
  <files>crates/hephaestus-core/tests/integration.rs</files>
  <action>
    Create a new integration test file at crates/hephaestus-core/tests/integration.rs. The entire file is gated behind cfg(feature = "integration") so it does not compile or run during normal cargo test.

    Include a shared async helper function download_model that takes an org string, a repo string, and a list of filenames to download. It uses hf_hub::HFClient to download each file, then returns the snapshot root directory (parent of onnx/ which is parent of model.onnx). This follows the same pattern as the existing classifier_e2e.rs download_test_model function.

    Write the following test functions, each marked with tokio::test:

    1. test_classifier_positive_sentiment:
       Model: Xenova/distilbert-base-uncased-finetuned-sst-2-english.
       Files to download: onnx/model.onnx, tokenizer.json, config.json.
       Input text: "I love this movie!" (known positive).
       Assertions: label equals "POSITIVE", score is greater than 0.5 and at most 1.0.

    2. test_classifier_negative_sentiment:
       Same model as above.
       Input text: "This is terrible and I hate it" (known negative).
       Assertions: label equals "NEGATIVE", score is greater than 0.5 and at most 1.0.

    3. test_embeddings_dimension_and_norm:
       Model: Xenova/multi-qa-distilbert-cos-v1.
       Files to download: onnx/model.onnx, tokenizer.json, config.json (if present, otherwise just onnx/model.onnx and tokenizer.json).
       Input text: "How do I reset my password?"
       Assertions: output Vec length equals 768, L2 norm is approximately 1.0 (within 1e-4), all values are finite f32.

    4. test_token_classifier_ner_entities:
       Model: Xenova/bert-base-NER.
       Files to download: onnx/model.onnx, tokenizer.json, config.json.
       Input text: "John Smith works at Google in Mountain View, California."
       Assertions:
       - At least one entity is returned
       - All entity scores are in [0.0, 1.0] (this validates the softmax fix from Plan 08-01)
       - At least one entity has label "PER" (for John Smith)
       - At least one entity has label "ORG" (for Google)
       - Each entity has start less than end (valid span)
       - Each entity word field is non-empty

    All pipelines are constructed with ExecutionProvider::Cpu. Each test creates its pipeline using the appropriate constructor (ClassifierPipeline::new, EmbeddingsPipeline::new, TokenClassifierPipeline::new), calls prepare() then execute().

    Do NOT create a seq2seq integration test. Fused single-pass seq2seq models with baked-in beam search are not reliably available in the Xenova namespace with a compatible output format. The three profiles tested (classifier, embeddings, token_classifier) cover the critical paths. Add a comment at the top of the file documenting that seq2seq is excluded due to lack of a reliable fused ONNX model for testing.

    Keep the existing classifier_e2e.rs file unchanged. The new integration.rs file supersedes it with more thorough assertions but does not delete it.
  </action>
