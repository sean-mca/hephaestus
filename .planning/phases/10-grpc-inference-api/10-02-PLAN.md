Create crates/hephaestus-api/src/grpc/inference.rs implementing the InferenceService trait:

1. Define GrpcInferenceService struct holding Arc<AppState>. Add a pub fn new(state: Arc<AppState>) constructor. Document both with doc comments.

2. Implement the tonic-generated InferenceService trait (from hephaestus_proto::v1::inference_service_server::InferenceService) with a single async fn infer method.

3. The infer method must follow the same control flow as the HTTP handler in handlers.rs:
   - Check state.is_ready(), return Status::unavailable if not ready.
   - Validate text is non-empty, return Status::invalid_argument if empty.
   - Create StageTimer and record request_start Instant.
   - Wrap inference in tokio::time::timeout using state.request_timeout().
   - Inside the timeout: if batching is enabled, use the read-lock-prepare then batcher submit path (dropping the read lock before submit per anti-lock-across-await). If batching is disabled, use the read-lock-prepare then write-lock-execute path (dropping read lock before acquiring write lock).
   - On timeout, return Status::deadline_exceeded.
   - On inference error, convert via ApiError::from then into tonic::Status.
   - On success, call finish_request on the timer, compute latency_ms, log the tracing::info event with model_id/latency_ms/status fields matching the HTTP handler pattern.
   - Convert the serde_json::Value output to an InferResponse proto message using a private helper function build_infer_response.

4. The build_infer_response function takes output: serde_json::Value, model_id: &str, latency_ms: u64 and returns InferResponse. It inspects the JSON keys to determine the profile:
   - If "label" key exists: build ClassificationResult with label string and score f32.
   - If "embedding" key exists: build EmbeddingResult with values vec of f32.
   - If "entities" key exists: build TokenClassificationResult with Entity proto messages converted from the JSON array (each entity has word, entity, score, start, end fields).
   - If "generated_text" key exists: build Seq2SeqResult with the text string.
   - Set model_id and latency_ms on the InferResponse, put the result variant in the oneof result field.

5. Add From<ApiError> for tonic::Status implementation in crates/hephaestus-api/src/error.rs:
   - NotReady -> Status::unavailable("service not ready")
   - BadRequest(msg) -> Status::invalid_argument(msg)
   - Tokenization(msg) -> Status::invalid_argument with "tokenization failed: " prefix
   - Timeout -> Status::deadline_exceeded("inference timeout")
   - Inference, Model, Internal -> Status::internal("internal server error") (same information-hiding as the HTTP handler, log the detailed error server-side)
   This requires adding tonic as a dependency, which was already added to the crate Cargo.toml above.

6. Add unit tests in a #[cfg(test)] mod tests block at the bottom of inference.rs:
   - test build_infer_response with classifier JSON output (assert label and score fields in the oneof)
   - test build_infer_response with embedding JSON output (assert values length)
   - test build_infer_response with token_classification JSON output (assert entities count and first entity fields)
   - test build_infer_response with seq2seq JSON output (assert generated_text field)

7. Add unit tests in error.rs #[cfg(test)] mod for the new tonic::Status conversion:
   - test ApiError::NotReady converts to Status with code UNAVAILABLE
   - test ApiError::Timeout converts to Status with code DEADLINE_EXCEEDED
   - test ApiError::Tokenization converts to Status with code INVALID_ARGUMENT
   - test ApiError::Inference converts to Status with code INTERNAL

All public items must have doc comments per doc-all-public rule.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gRPC client -> InferenceService | Untrusted gRPC requests cross into inference pipeline |
| gRPC client -> HealthService | Untrusted health check requests (low risk, read-only) |
| gRPC client -> ReflectionService | Untrusted reflection queries (information disclosure, acceptable for internal service) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-02 | Denial of Service | gRPC Infer RPC | medium | mitigate | Server-side request timeout via tokio::time::timeout (same as HTTP handler). Tonic default max message size (4MB) limits payload. Tokenizer truncation at 512 tokens limits CPU cost. |
| T-10-03 | Information Disclosure | gRPC error responses | medium | mitigate | Internal errors (Inference, Model, Internal variants) mapped to generic Status::internal message. Detailed error logged server-side only. Same pattern as HTTP ApiError::IntoResponse. |
| T-10-04 | Information Disclosure | ReflectionService | low | accept | Server reflection exposes service definitions and message types. Acceptable for internal cluster service. For external exposure, gate behind feature flag in future phase. |
| T-10-05 | Spoofing | HealthReporter sync | low | mitigate | HealthReporter updated in same code path as AtomicBool readiness (set_ready + set_service_status called together). Prevents inconsistent health state between gRPC and HTTP probes. |
| T-10-SC | Tampering | cargo dependency installs | medium | mitigate | All packages verified in RESEARCH.md Package Legitimacy Audit. No ASSUMED or SUS packages. |
