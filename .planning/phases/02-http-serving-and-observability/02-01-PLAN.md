    **Step 1 -- Graceful shutdown signal (crates/hephaestus/src/main.rs)**

    Per RESEARCH Pattern 3 and D-07, add a shutdown_signal async function:
    - Accept state: Arc of AppState as parameter
    - Use tokio::select! to wait for either ctrl_c or SIGTERM (unix signal)
    - On signal receipt: log "shutdown signal received, draining connections", then flip state.ready to false with SeqCst ordering (D-07 -- k8s stops routing new traffic)
    - The SIGTERM handler uses tokio::signal::unix::signal(SignalKind::terminate()) guarded with #[cfg(unix)]; for non-unix, use std::future::pending() as fallback

    Wire the shutdown signal into the axum::serve call from Task 1:
    - Change axum::serve(listener, app).await? to axum::serve(listener, app).with_graceful_shutdown(shutdown_signal(state.clone())).await?
    - After serve returns, log "server shut down" and call opentelemetry::global::shutdown_tracer_provider() as a no-op placeholder (Plan 02 activates OTel)

    **Enforce drain timeout per D-13 (crates/hephaestus/src/main.rs)**

    The with_graceful_shutdown call alone will wait indefinitely for in-flight requests to complete. D-13 requires a configurable upper bound on the drain period via SHUTDOWN_TIMEOUT_SECS. Before awaiting the serve future, spawn a background watchdog task that enforces this bound:
    - Capture config.shutdown_timeout_secs as a Duration before the serve call
    - Spawn a tokio task (the watchdog) that polls state.ready with Ordering::SeqCst in a loop (sleep 200ms between checks) until it observes false — meaning shutdown_signal has fired
    - Once readiness is false, the watchdog sleeps for the configured shutdown_timeout duration
    - If the watchdog timer expires (meaning the serve future has not yet returned), log a warning including the timeout value and call std::process::exit(1) to force termination
    - If the serve future completes before the watchdog fires, the watchdog task is dropped automatically when the tokio runtime shuts down — no cleanup needed
    - This ensures config.shutdown_timeout_secs is actively enforced, not dead config
