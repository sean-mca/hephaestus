Implement the ASR pipeline (CTC and Whisper model support), model profile detection, audio preprocessing modules, and wire the complete WebSocket-to-transcript data path. Purpose: Complete the Phase 11 goal — real-time audio transcription via WebSocket. CTC models (wav2vec2) use raw waveform input with greedy decode. Whisper models use mel spectrogram input with autoregressive encoder-decoder inference. Both are hidden behind the AsrPipeline deep-module interface.
Output: Working ASR inference through WebSocket. Configurable via env vars. Existing text pipelines unchanged.

The Whisper-specific check MUST come before the generic ForConditionalGeneration check to avoid misdetecting Whisper as Seq2Seq. Create crates/hephaestus-core/src/ctc.rs. Define a pub function ctc_greedy_decode that accepts: logits (a slice of f32, flattened [timesteps * vocab_size]), num_timesteps (usize), vocab_size (usize), vocab (a slice of String), and blank_id (usize). The algorithm: iterate over timesteps 0..num_timesteps. For each timestep, slice the logits from t*vocab_size to (t+1)*vocab_size. Find the argmax index (the token with highest logit value). If the argmax is not blank_id AND not equal to the previous token, look up vocab[argmax] and push it to a decoded vec. Track prev_token across iterations, initialized to blank_id. After the loop, join the decoded strings with empty separator and return the result String. Add unit tests: test with known logits where tokens [1, 1, 0, 2, 2, 0, 3] (where 0 is blank) should decode to vocab entries for indices 1, 2, 3 concatenated. Test with all-blank input returning empty string. Test with single token returning that token.

Create crates/hephaestus-core/src/mel.rs. Add mel_spec = "0.4" to hephaestus-core/Cargo.toml workspace or direct dependency. This module wraps the mel_spec crate to compute Whisper-compatible log-mel spectrograms. Read the mel_spec crate documentation (docs.rs or source) to understand its API before implementing. The module should expose a pub function compute_mel_spectrogram that accepts: audio samples (slice of f32), n_fft (usize, typically 400 for Whisper), hop_length (usize, typically 160), n_mels (usize, typically 80 or 128), and sample_rate (u32, 16000). It should return a Result of ndarray::Array2 of f32 (shape [n_mels, num_frames]) wrapped in CoreError. The implementation wraps mel_spec crate calls. If the mel_spec API does not directly provide the needed function signature, build the mel spectrogram step-by-step using mel_spec primitives (STFT, mel filterbank, log scaling). Apply log10 scaling and clamp to match Whisper preprocessing (log_spec = max(log10(mel_spec), log10(1e-10)), then (log_spec + 4.0) / 4.0 for normalization). Pad or truncate the time dimension to the expected frame count (n_fft/hop_length frames per 30s of audio = 3000 for Whisper). Add a unit test that computes mel features for a simple sine wave and verifies the output shape is [n_mels, expected_frames] and all values are finite.

In pipeline.rs, define an AsrMode enum (private to the module) with two variants: Ctc and EncoderDecoder. Define an AsrPipeline struct with fields: encoder_session (Session — used for both CTC single model and Whisper encoder), decoder_session (Option of Session — Some for Whisper, None for CTC), tokenizer (Option of Tokenizer — Some for Whisper which uses tokenizer.json, None for CTC), vocab (Vec of String — loaded from vocab.json for CTC, empty for Whisper), blank_id (usize — blank token index for CTC, typically 0), mode (AsrMode), feature_extractor (String — "mel" or "none"), n_mels (usize), n_fft (usize), hop_length (usize), decoder_start_token_id (usize — from config.json for Whisper), eos_token_id (usize — from config.json for Whisper), max_target_positions (usize — from config.json for Whisper, default 448).

Implement AsrPipeline::new accepting model_dir (Path), ep (ExecutionProvider reference), and feature_extractor (str reference). Read config.json to detect model type. If architectures contains a string ending with "ForCTC", set mode to Ctc: load model.onnx (with onnx/ subdirectory fallback, same pattern as load_session_and_tokenizer but without tokenizer validation since ASR models use input_values not input_ids). Load vocab.json as a HashMap of String to usize, invert to Vec of String indexed by id. Set blank_id to the id mapped to the pad token or pipe character (check for key "<pad>" first, then "|", default to 0). If architectures contains "WhisperForConditionalGeneration", set mode to EncoderDecoder: load encoder_model.onnx from the onnx/ subdirectory. Load decoder_model_merged.onnx from the same directory. Load tokenizer.json via the Tokenizer crate. Read n_mels from preprocessor_config.json (feature_size field, default 80). Read n_fft (default 400) and hop_length (default 160) from preprocessor_config.json. Read decoder_start_token_id (default 50258), eos_token_id (default 50257), and max_target_positions (default 448) from config.json. Build the ExecutionProvider list and configure sessions with Level3 optimization (same as existing load_session_and_tokenizer pattern).

Implement Pipeline trait for AsrPipeline with Input = Vec of f32, Prepared = PreparedAudio, Output = String.

For prepare: if feature_extractor is "mel", call mel::compute_mel_spectrogram with the audio samples and the stored n_fft, hop_length, n_mels, sample_rate (16000). Reshape the result to [1, n_mels, num_frames] by inserting a batch dimension. Construct PreparedAudio with features set to this 2D array (reshape to [n_mels, num_frames] for the Array2 and handle the batch dim at execute time) and raw_samples set to None. If feature_extractor is "none", construct a 2D array of shape [1, samples.len()] from the audio samples. Construct PreparedAudio with features set to this array and raw_samples set to Some of the original samples vec (preserved for potential length-dependent processing).

For execute in CTC mode: construct an ndarray tensor from prepared.features (shape [1, num_samples] for raw waveform). Build ort inputs with name "input_values" mapped to the tensor. Run self.encoder_session. Extract the output logits tensor (shape [1, timesteps, vocab_size]). Get timesteps and vocab_size from the shape. Flatten the logits data and call ctc::ctc_greedy_decode with the logits, timesteps, vocab_size, self.vocab, and self.blank_id. Return the decoded string.

For execute in EncoderDecoder mode (Whisper): construct a 3D ndarray tensor from prepared.features with shape [1, n_mels, num_frames] (add batch dimension). Run the encoder session with input name "input_features" mapped to the features tensor. Extract the encoder output hidden state. Initialize a tokens vec with the decoder_start_token_id as the first token. Loop up to max_target_positions iterations: construct decoder_input_ids as a 2D i64 array of shape [1, tokens.len()] from the accumulated tokens. Run the decoder session with inputs "input_ids" (or "decoder_input_ids" — check the model input names at load time and use whichever is present) mapped to the token ids tensor and "encoder_hidden_states" mapped to the encoder output. Extract the logits from decoder output (shape [1, seq_len, vocab_size]). Take the logits for the last position (offset = (tokens.len() - 1) * vocab_size). Find the argmax token. If argmax equals eos_token_id, break. Otherwise push argmax to tokens. After the loop, convert tokens to u32 ids and call tokenizer.decode (skip special tokens = true). Return the decoded text. Wrap all ort errors in CoreError::Inference.

Add PipelineKind::Asr(AsrPipeline) variant to the PipelineKind enum. In PipelineKind::prepare, add match arms: (Self::Asr(p), InferenceInput::Audio(audio)) dispatches to p.prepare(audio) and wraps in PreparedData::Audio. (Self::Asr(_), InferenceInput::Text(_)) returns CoreError::InvalidInput with "ASR pipeline requires audio input". In PipelineKind::execute, add: (Self::Asr(p), PreparedData::Audio(a)) dispatches to p.execute(a) and wraps in PipelineOutput::Asr. In PipelineKind::execute_batch, add a match arm for Self::Asr that returns an error for each item stating ASR does not support batching (per D-03). Also update the needs_tti check in execute_batch to handle Self::Asr (return false — ASR models do not use token_type_ids).

In lib.rs, add re-exports for AsrPipeline. Add pub mod ctc and pub mod mel to the module declarations.

Add unit tests for profile detection (in profile.rs tests module as described above). Add unit tests for ctc_greedy_decode (in ctc.rs). The mel.rs test verifies output shape.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client to WebSocket | Untrusted audio bytes converted to f32 samples cross into the ASR pipeline |
| WebSocket handler to Pipeline | Validated f32 audio samples cross the prepare/execute boundary |
| ONNX model files | Model files loaded from disk could contain adversarial weights (mitigated by existing model resolution chain) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-07 | Tampering | AsrPipeline model loading | medium | mitigate | Validate ONNX input names at load time. CTC models must have "input_values" input. Whisper models must have "input_features" on encoder and "decoder_input_ids" or "input_ids" on decoder. Reject models with unexpected input names. |
| T-11-08 | Denial of Service | Whisper decoder loop | medium | mitigate | Autoregressive decode loop bounded by max_target_positions (default 448 tokens). Prevents infinite generation from adversarial encoder output. |
| T-11-09 | Denial of Service | RwLock starvation under WebSocket load | medium | accept | Many concurrent WebSocket connections acquiring write locks for execute() may increase REST/gRPC latency. Documented as known trade-off per D-03 (each connection runs independently). Future mitigation: per-connection pipeline cloning or connection queuing (deferred). |
| T-11-10 | Tampering | Config env var injection | low | mitigate | FEATURE_EXTRACTOR and CHUNKING_STRATEGY validated against explicit allowlists ("mel"/"none" and "windowed"/"streaming") in Config::validate. Invalid values rejected at startup. |
| T-11-SC | Tampering | cargo installs | medium | mitigate | mel_spec 0.4.0 verified in Package Legitimacy Audit (3 yrs, 33K/wk, github.com/wavey-ai/mel-spec, verdict OK). No ASSUMED or SUS packages. |
