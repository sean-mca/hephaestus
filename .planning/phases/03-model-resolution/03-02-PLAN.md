## Phase Goal

**As a** Kubernetes operator, **I want to** specify only a model name and have the runtime automatically resolve ONNX files from S3 cache or HuggingFace, **so that** pods self-provision without requiring pre-downloaded model files.

<objective>
Add the S3 cache tier (tier 1), background cache-back upload, and Forge client stub (tier 3) to the ModelResolver, completing the full 3-tier resolution chain. D-01, D-02, D-06, D-08, D-10, D-11, D-12, D-13, D-14 are implemented.

After this plan, the complete resolution flow works: S3 cache check (with retry) -> HuggingFace download (with retry) -> Forge conversion (stub returns error) -> background S3 cache-back after HF success. The resolver is fully feature-complete for Phase 3.

Purpose: S3 cache eliminates HuggingFace dependency for warm pods. Cache-back ensures first-pod HF downloads benefit all subsequent pods. Forge stub provides clean error messaging and trait contract for Phase 5.

Output: Complete 3-tier ModelResolver with S3 operations, Forge stub, and background cache-back.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-04 | Tampering | S3 key construction from MODEL_ID | medium | mitigate | MODEL_ID from env vars (operator-controlled). aws-sdk-s3 handles URL encoding for S3 keys. Validate model_id before constructing S3 keys -- reject path traversal components (..) in model_id segments. |
| T-03-05 | Tampering | Atomic download race condition | medium | mitigate | TempDir::new_in(same_filesystem) + tokio::fs::rename ensures atomic visibility. into_path() prevents destructor cleanup. No window where partial files are visible to the pipeline. |
| T-03-06 | Spoofing | FORGE_URL SSRF | low | accept | FORGE_URL from env vars (operator-controlled, not user input). reqwest default redirect policy limits redirect hops. Phase 3 stub never makes HTTP calls. |
| T-03-07 | Denial of Service | Concurrent S3 uploads from multiple pods | low | accept | D-13 explicitly accepts redundant uploads. S3 PutObject is idempotent. No corruption risk from concurrent writes. |
| T-03-SC | Tampering | cargo dependency installs | high | mitigate | Package Legitimacy Audit passed: aws-sdk-s3 (OK, 1.4M/wk, official AWS), aws-config (OK, 2.2M/wk, official AWS), reqwest (OK, 13M/wk, seanmonstar/reqwest). No [ASSUMED] or [SUS] packages. |
